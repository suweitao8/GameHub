# GameHub UP 主主页设计

## 目标

参考用户提供的 UP 主主页信息层级，重做 `/games/author/:accountId` 的作者主页视觉结构，让作者身份、四项真实统计和全部游戏形成直接的首页阅读路径，同时继续使用 GameHub 当前真实 API 数据和路由功能。

## 现状

当前作者页已有封面渐变、头像资料、统计栏、主页/动态/投稿/合集标签、置顶作品、游戏网格和右侧资料卡，但这些辅助分区与 GameHub 当前“作者只维护游戏主页”的产品范围不符，且置顶卡会重复展示第一款游戏。

## 方案

- 保留全局 GameHub 顶部导航和现有作者 API，不虚构直播信息；作者响应补充已有 Actor 的 `followingCount` 字段。
- 将作者头部调整为带视觉横幅的 hero 区：作者头像覆盖在底部，右侧展示昵称、简介、关注按钮和轻量身份标签。
- 将唯一的“主页”标识与统计信息放入同一条白色横向信息栏，按顺序展示关注数、粉丝数、获赞数和游玩数；桌面端统计靠右，窄屏在栏内横向滚动。
- 主页内容直接展示全部开发的游戏，保留最新发布、最多游玩、最多收藏三种排序，不再提供动态、投稿、合集、置顶作品或右侧资料卡。
- 旧链接中的 `tab` 查询参数不再切换面板，始终回到同一个作者主页；排序和关注交互继续使用现有 URL/API 合同。
- 桌面端保持全宽五列游戏卡片；中等宽度缩减为四列，窄屏为两列，头像、关注按钮、统计和卡片保持可操作，不产生页面级横向溢出。
- 视觉使用现有 GameHub token、浅色表面、蓝色品牌色和少量橙/粉强调色；横幅使用 CSS 几何渐变，不直接复制参考图素材。

## 验证

- 静态契约要求作者页包含 hero、同排主页统计、全量游戏排序和响应式五列网格，并检查已移除的动态/投稿/合集、置顶和侧栏结构不会回归，同时检查作者 API 的关注数映射和响应版本参数。
- 运行作者页模板 lint、相关 SCSS lint 和生产 client build。
- 浏览器检查 `/games/author/2` 在 1440px、768px、375px 下直接展示全部游戏、无横向溢出、排序链接和关注按钮状态；访问旧 `tab=games` 链接时仍保持同一主页。
- 运行 `/api/v1/ping`、作者 API 和完整 `self-test:gamehub`，如有仓库既有契约失败需单独记录，不修改无关模块。
