# 游戏导航栏视觉与响应式布局设计

## 目标

将游戏体验页顶部导航栏改为纯白背景，移除顶部背景图，并让桌面端导航栏在滚动前后保持固定高度；同时让游戏发现页的动态、热门和分类入口按屏幕宽度自适应铺满。

## 现状

`client/src/app/header/header.component.scss` 为游戏体验页导航栏设置了背景图，并使用 `--header-height` 控制布局。`client/src/app/app.component.scss` 在桌面端把游戏体验页的导航高度从 200px 切换到滚动后的 50px，导致导航栏随滚动收缩。

游戏发现页的动态、热门和分类入口分成两个固定尺寸的 flex 容器，前两个入口宽度固定，分类入口占据剩余空间；在不同屏幕宽度下会出现比例不一致或横向空间未被统一利用的问题。

## 方案

- 游戏体验页导航栏背景固定为 `#fff`，背景图关闭。
- 桌面端 `--header-height` 固定为 `56px`，不再使用 200px 展开高度或 50px 滚动高度。
- 移动端继续保留现有 `58px` 高度和响应式布局。
- 保留边框、阴影、导航内容和现有交互，仅改变背景与高度。
- 将动态、热门和分类入口放入同一个横向导航容器，宽屏使用 `grid-auto-columns: minmax(clamp(3.8rem, 5vw, 4.2rem), 1fr)` 让所有入口等宽并铺满可用空间。
- 窄屏保留入口最小宽度并允许导航容器横向滚动，避免文字和点击区域被压缩；路由顺序、颜色、sticky 定位和分类状态样式保持不变。

## 验证

- 客户端 SCSS/TypeScript lint。
- 生产 client build。
- 浏览器检查 `/games/author/2`：背景色为白色、无背景图、桌面端高度为 56px，滚动前后不变化；移动端没有横向溢出。
- 浏览器检查 `/games`：在 1440px 宽屏下所有导航入口等宽并填满容器，在 768px 和 375px 下入口保持最小宽度、容器可横向滚动且页面本身无横向溢出；点击动态和热门后分别到达 `/games/activity` 与 `/games?sort=popular`。
