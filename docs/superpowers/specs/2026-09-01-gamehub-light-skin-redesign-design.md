# GameHub 浅色皮肤重构设计规格

## 设计判断

Reading this as: 面向日常浏览和游玩的 HTML5 游戏社区重构，用户希望从五颜六色的视觉转向可信、安静、清晰的浅色产品界面，采用 mydrama 浅色皮肤的语义令牌体系，并保留游戏内容本身。

设计参数：

- `DESIGN_VARIANCE: 5`。保留游戏中心的内容密度与网格，但不再通过随机色块制造变化。
- `MOTION_INTENSITY: 3`。只保留 hover、focus、active 和必要的状态过渡，不新增装饰性动画。
- `VISUAL_DENSITY: 4`。使用日常应用的标准间距，内容足够紧凑，但每个层级有明确留白。

## 背景与问题

当前 GameHub 已经有一套蓝品牌令牌，但大量运行中的页面仍然直接使用高饱和色、渐变、按标题随机生成的彩色占位封面和按图片平均色取样的推荐背景。结果是：

1. 页面底色、卡片、按钮和封面占位都在争夺注意力，用户无法快速识别内容层级。
2. 首页推荐区、游戏卡片、社区和账户页面没有共享的表面、边框、文字和状态规则。
3. 搜索框存在输入框外层和下拉容器重复绘制边框的情况，截图中看起来像两个搜索框叠在一起。
4. 当前全局样式已经部分改成蓝品牌，但旧的彩色组件仍然被真实路由加载，局部换色不能解决整体观感。

## 目标

- 以 mydrama 浅色皮肤的低饱和语义体系为参考，建立 GameHub 的单一浅色页面主题。
- 清除产品壳层中的多彩占位封面、页面渐变、平均色动态背景和无语义的装饰色。
- 保留用户上传的真实游戏封面、游戏运行时内容、已有路由、文案、API 和交互含义。
- 统一首页、游戏详情、作者、投稿、社区、个人库、通知、账户和认证页面的层级、间距、圆角、边框与状态。
- 让搜索输入框只有一个可见边框，热门搜索结果作为独立下拉面板定位在输入框下方。
- 在桌面和窄屏下都不产生横向溢出，键盘焦点和异步状态保持可见。

## 非目标

- 不改 URL、路由、导航标签、表单字段名称、API、权限或数据模型。
- 不改游戏 iframe 内部的游戏视觉，不把真实上传封面强行灰度化。
- 不重写翻译源文件，不手工修改生成的 locale 文件。
- 不删除仍被 standalone player 或 embed 兼容路径使用的旧代码。删除 `cover-tone` 相关代码前必须先完成引用审计。
- 不新增 UI 依赖或图标依赖。

## 参考主题与令牌契约

参考来源为 `D:\Github\mydrama\frontend\src\index.css` 和 `D:\Github\mydrama\DESIGN.md` 的 light token。GameHub 会将它们转译为现有 SCSS/CSS 自定义属性，不直接复制 mydrama 的组件代码。

### 页面颜色

| 语义 | 目标值 | 用途 |
| --- | --- | --- |
| page background | `#f5f5f5` | 页面根背景 |
| surface | `#ffffff` | 卡片、面板、表单 |
| surface muted | `#f0f2f5` | 次级块、禁用背景、占位 |
| border | `#e0e0e0` | 普通分隔线 |
| border soft | `#e9edef` | 卡片和控件的轻边界 |
| text | `#111b21` | 标题和正文 |
| text muted | `#667781` | 元数据和辅助说明 |
| primary | `#008198` | 主按钮、选中状态、关键交互 |
| primary foreground | `#ffffff` | primary 上的文字和图标 |
| accent | `#3b82f6` | 链接、焦点环和少量辅助状态 |
| danger | 现有语义危险色 | 删除、错误和失败状态 |
| success | 现有语义成功色 | 成功、可用和完成状态 |
| warning | 现有语义警告色 | 警告状态，不作装饰 |

### 几何与文字

- 间距基线：4、8、12、16、24、32px。
- 圆角：控件 12px，卡片 14px，面板 16px，特殊大容器最多 20px，胶囊只用于短标签和筛选控件。
- 阴影：优先使用边框；需要层级时使用低透明度的冷灰阴影，不使用彩色发光。
- 字体：沿用项目已加载的 Source Sans 3 与 CJK fallback，不新增字体；标题使用 600 或 700，正文 400，元数据 12 或 14px。
- 页面最大内容宽度沿用当前布局约束，主内容使用 16px 到 32px 的响应式内边距。

## 页面与组件方案

### 应用壳层

- Header 使用白色表面、1px 底边框和稳定高度。
- Logo、主导航、搜索、账户操作共享一条基线；桌面端不换行。
- 导航选中态使用浅青灰底和 primary 文字，不再使用蓝粉并列的大色块。
- 页面背景统一为 page background，内容区域不再叠加全屏渐变。

### 搜索

- 搜索输入本身是唯一的 bordered control，使用 `surface` 背景、`border` 边框和 `primary` focus ring。
- 外层容器只负责相对定位和宽度，不设置第二个 border、box-shadow 或 background。
- 热门搜索、联想和空结果都放在同一个独立 popover panel 中，使用 `surface`、soft border 和轻阴影，顶部紧贴输入框。
- 关闭、键盘导航、空结果和加载状态沿用当前业务行为；只修复 DOM/CSS 层叠，不改变查询逻辑。
- 搜索建议列表保持可键盘到达，输入框有明确 aria-label，面板状态不遮挡页面主内容之外的必要控件。

### 游戏卡片与推荐区

- 卡片采用白色表面、细边框、14px 圆角和极轻阴影，标题、作者、日期和统计统一为正文与元数据层级。
- 有真实封面时只显示真实封面和必要的可读性遮罩，不根据图片采样改变卡片或页面背景。
- 没有封面时使用单一的浅灰表面和低对比度的中性首字母/类别标识，不再输出 `cover-tone-0` 到 `cover-tone-9`。
- 推荐焦点区使用白色面板和固定的低对比度信息层；保留轮播切换、键盘操作和加载占位，但取消动态彩色 fade。
- 标签只表达真实类别、推荐或状态，不作为色彩装饰。类别标签使用同一中性色或 primary 的浅底。

### 其他页面

- 详情、作者、社区、收藏、通知、排行榜和账户页面统一使用 surface panel、section heading、muted metadata 和 semantic action。
- 表单、上传、编辑器和对话框使用相同的 label、input、help、error 和 action 结构。
- Toast、错误、成功和警告保留语义颜色，禁止把状态颜色扩散到普通卡片和导航。
- Analytics 图表可以保留可辨识的数据系列色，但使用受控、低饱和的图表调色板，不影响页面主题。
- 游戏播放 iframe 和其控制条继续使用深色运行时外壳，外层说明和相关游戏区域使用新的浅色壳层。

## 交互与可访问性

- 所有现有交互入口保留 hover、focus-visible、active、disabled、loading、empty、error 和 success 状态。
- Focus ring 使用可见的 primary 或 accent 环，不以 `outline: none` 代替。
- 触控目标不小于 44px；窄屏的筛选和横向内容不强制页面整体横向滚动。
- 图片 alt、图标按钮 aria-label、对话框的 Esc 与遮罩关闭行为保持现有契约。
- 不新增循环动画；现有必要动画在 `prefers-reduced-motion: reduce` 下退化为即时状态变化。
- 颜色和文字对比度以 WCAG AA 为下限，尤其检查 placeholder、disabled、错误文字和 primary 按钮。

## 实施边界

改动按以下层次进行：

1. 重新定义 `game-community.tokens.scss` 和 `gamehub-ui.scss` 的浅色语义变量，并保留对 Bootstrap/PrimeNG 的兼容映射。
2. 更新 Header、搜索、首页推荐、游戏卡片和共享状态组件，使它们只消费语义变量。
3. 批量收敛游戏域和账户/认证页面的局部颜色、渐变、阴影、圆角和表面规则。
4. 清理无引用的占位色辅助函数；仍被引用的逻辑只保留内容所需的首字母能力。
5. 更新样式静态验证器，使其检查 mydrama light contract，并禁止产品壳层重新引入多彩 placeholder 和动态封面渐变。

## 验收标准

- `/games` 桌面截图的页面背景、Header、推荐区、卡片和搜索面板均符合上述浅色令牌；看不到按标题随机生成的红黄紫蓝占位卡。
- 搜索框只有一层输入边框，热门搜索面板与输入框有清晰的上下关系，不再出现截图中的双框。
- 真实封面仍可显示，游戏播放页的深色 runtime frame 不被误改为浅色。
- 至少验证首页、游戏详情、社区/个人库、账户或认证页面各一条真实路由，并覆盖一个异步/空状态。
- 内置浏览器验证桌面宽度和 375px 左右窄屏，页面无横向溢出，搜索键盘交互可用。
- `pnpm run verify:gamehub-client`、`pnpm run build:client:light`、`pnpm run build:server` 和最终 `pnpm run self-test:gamehub` 均有新鲜成功证据；任何无法运行的门禁必须明确记录原因。
