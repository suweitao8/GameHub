# GameHub 投稿入口闭环设计

## 已确认的问题

`/games/upload` 已被 `GameLoginGuard` 正确保护，未登录访问会保留
`returnUrl=/games/upload`。不过顶部“投稿”仍只是一个普通链接：用户在未登录时
会被守卫静默带到登录页，看不到这是继续投稿所需的登录步骤；在桌面宽度下，位于
页面中心的绝对定位游戏导航还可能与右侧操作区竞争点击层。

上传页本身已有文件选择、拖放、键盘触发、加载、错误和成功状态，因此不应重做表单。

## 目标

1. 顶部投稿入口始终是独立、可点击的右侧操作区，不被居中的游戏导航遮挡。
2. 未登录点击投稿时，明确导航到 `/login?returnUrl=%2Fgames%2Fupload`；登录成功后
   现有登录页会自动回到上传页。
3. 已登录点击投稿时，直接前往上传页。
4. 保留原生链接回退、键盘可达性、可见焦点和移动端布局。

## 实现边界

- 在 `HeaderComponent` 中集中处理投稿点击和回跳地址，不改动守卫或登录页的已验证回跳逻辑。
- 将顶部中间导航明确置于底层，右侧操作区置于可交互层，避免重叠区域命中错误元素。
- 更新 `scripts/verify-gamehub-client.mjs`，把入口行为、回跳和层级关系固定为回归契约。
- 不改变上传文件校验、后端上传 API、用户认证模型或主工作区已有导航栏改动。

## 验收

- 静态回归检查先在基线上失败，修改后通过。
- 客户端轻量构建通过。
- 运行时 `/api/v1/ping` 返回 `pong`，浏览器真实点击投稿后进入带 `returnUrl` 的登录页（未登录场景）。
- 上传页仍可直接加载，并保留文件选择、拖放、键盘与提交反馈。
