# GameHub 合集与活动可信数据设计

## 已确认的问题

- 合集列表接口把每个 `gameCount` 固定返回为 `0`，详情还会展示未发布游戏；共享模型与实际 JSON 字段也不一致。
- 活动详情用参与者列表的前 100 项来判断当前用户是否已报名。超过 100 人时，已报名用户会被误判为未报名。
- 报名与取消报名未使用同一事务更新参与关系和人数，且后端没有容量检查；并发请求可能让人数与实际参与记录不一致。

## 目标

1. 合集列表和详情只统计、展示已发布游戏，并通过共享 API 模型返回真实作品数。
2. 活动详情通过一个需登录、不可缓存的参与状态接口获得当前用户的精确报名状态。
3. 报名和退出在锁定活动行的事务内同时写入参与记录和 `participantCount`，后端强制执行报名容量。
4. 前端只使用后端返回的最新人数，不再猜测增减；未登录报名明确转至登录并保留当前活动链接。
5. OpenAPI、共享模型和 Angular 组件使用同一字段结构，不保留 `unknown as` 规避类型漂移。

## 非目标

- 不在本批次虚构文章内容或引入新的后台运营界面。
- 不改变活动的创建、编辑权限模型。
- 不新增数据库表或改变历史迁移；现有活动和合集表已经包含所需字段与索引。

## 验收

- 合集 API 的列表和详情计数来自已发布作品，而不是常量。
- 参与状态接口只返回当前认证用户的 `joined` 状态，活动公共详情继续可缓存。
- 同一活动容量满时，后端返回冲突，且所有成功的报名/取消操作返回准确人数。
- 客户端构建、服务端构建、OpenAPI 校验和 GameHub 自检通过；测试覆盖实际 API 响应与容量路径。
