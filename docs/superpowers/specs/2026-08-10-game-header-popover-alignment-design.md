# GameHub 游戏导航弹窗与投稿按钮对齐设计

## 背景

游戏页顶部导航中的“历史”和“创作中心”弹窗使用了与通用弹窗不同的边缘定位，但复用了会写入 `translateX(-50%)` 的淡入动画，导致弹窗偏离对应入口。顶部“投稿”按钮使用 flex 布局，但文字继承的行高造成视觉上偏上。

## 目标

- 历史弹窗的主体和箭头以“历史”入口图标为水平锚点。
- 创作中心弹窗的主体和箭头以“创作中心”入口图标为水平锚点。
- 保留弹窗淡入效果，不让动画覆盖弹窗的横向定位。
- 投稿按钮保留现有尺寸、颜色、交互和文案，仅修正文字的垂直视觉居中。
- 桌面端和窄屏桌面端不产生新的横向溢出或遮挡。

## 非目标

- 不改变导航入口、路由、弹窗内容、悬停/键盘触发逻辑。
- 不调整移动端隐藏游戏快捷入口的现有策略。
- 不引入新的依赖或修改全局设计 token。

## 设计

### 弹窗定位

统一弹窗的横向定位语义：弹窗默认以 action wrapper 的中心为锚点，历史和创作中心不再使用脱离入口的固定右侧定位。淡入动画只复用同一横向偏移并叠加短暂的纵向位移，避免动画结束时覆盖定位规则。

弹窗箭头沿用同一锚点，并为靠近右侧的入口保留明确的箭头位置规则。通过桌面宽度和窄屏宽度的真实浏览器检查确认弹窗仍在可视区域内；如果可视区域不足，使用现有最大宽度约束，不扩大弹窗内容。

### 投稿按钮

保持 `.game-submit-button` 的现有高度、水平内边距、颜色、圆角、hover/focus/active 行为，仅设置明确的行高并保留 flex 的 `align-items: center`，让文字行盒在按钮高度内稳定居中。

### 可访问性与交互

- 不改变原有链接和弹窗入口的键盘可达性。
- 保留现有 `focus-visible` 轮廓。
- 弹窗仍由原有 pointer/focus 状态控制，保持进入弹窗后不立即关闭。
- 图标继续作为装饰性内容，不新增重复的可读标签。

## 实现范围

- `client/src/app/header/header.component.scss`：调整弹窗定位/动画的 CSS 契约和投稿按钮行高。
- `scripts/verify-gamehub-client.mjs`：增加回归契约，验证自定义弹窗不会被横向动画偏移，并验证投稿按钮包含明确的垂直对齐规则。

## 验证策略

1. 先运行回归契约，确认当前实现因历史/创作中心的定位与动画冲突而失败。
2. 完成最小 SCSS 修复后重新运行回归契约和变更文件的 Stylelint。
3. 构建客户端并运行 GameHub 自检门禁。
4. 在真实浏览器中检查：
   - 桌面端历史、创作中心弹窗主体中心与对应图标中心一致；
   - 弹窗箭头指向对应入口；
   - 投稿文字在按钮内垂直居中；
   - 窄屏下无新的横向溢出，键盘 focus-visible 仍可见。
