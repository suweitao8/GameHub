# 账户弹窗个人中心与统计设计

**日期：** 2026-08-30  
**范围：** GameHub 游戏态顶栏的已登录用户头像弹窗

## Design read

这是一个面向已登录玩家的账户浮层定向改版，保留 GameHub 现有浅色设计令牌、紧凑信息密度和圆角语言，优先补齐账户入口、关系数据和创作数量，不改变站点路由结构或引入新的 UI 依赖。

本次局部设计取值：`DESIGN_VARIANCE=4`、`MOTION_INTENSITY=3`、`VISUAL_DENSITY=5`。浮层需要比当前版本更有层次，但仍然服务于快速查看和跳转，不增加装饰性动画。

## 现状与问题

- 游戏态头像按钮点击后直接跳转到 `/games/author/:id`，用户无法通过点击头像打开个人菜单。
- 当前悬停卡只有头像、昵称、硬币和退出登录，没有“个人中心”入口。
- 当前登录用户对象已经带有 `account.followingCount` 和 `account.followersCount`，但没有在浮层展示。
- 现有 `GamesService.creatorOverview()` 请求返回 `gameCount`，并且当前浮层已经通过它获取硬币余额，所以动态数量可以直接使用现有数据请求。

## 目标

打开头像浮层后，玩家可以在一眼内完成以下事情：

1. 识别当前登录账号。
2. 查看关注数、粉丝数和动态数。
3. 进入“个人中心”。
4. 进入自己的公开主页。
5. 退出登录。

“动态”在本设计中保留用户要求的展示文案，但数值语义明确为当前账号发布的游戏数量，不使用通知流数量或活动条数。

## 方案

### 触发与关闭

- 鼠标移入头像区域时继续打开浮层，保留现有宽限关闭机制，允许鼠标从头像滑入卡片。
- 点击头像改为切换浮层，不再直接跳转作者主页。
- 头像按钮获得焦点时打开浮层，焦点移出头像容器后关闭。
- 在头像按钮或浮层内按 `Escape` 关闭浮层，并把焦点还给头像按钮。
- 点击浮层内的路由链接后由 Angular 正常导航，导航过程中浮层收起。
- 不使用遮罩或模态焦点陷阱。这个组件是非模态账户 popover，焦点应能在浮层内的链接和页面之间自然移动；因此使用普通链接和按钮语义，不伪装成阻塞式对话框。

### 浮层布局

浮层保持现有 `game-avatar-hover-card` 作为容器，采用从上到下的三段式布局：

1. **身份区**
   - 展示头像、显示名、账号名和硬币余额。
   - 显示名使用 `account.displayName`，缺失时回退到 `username`。
   - 账号名使用 `account.name`，缺失时不渲染空占位。

2. **统计区**
   - 三列等宽展示 `关注`、`粉丝`、`动态`。
   - `关注` 使用 `user.account.followingCount`。
   - `粉丝` 使用 `user.account.followersCount`。
   - `动态` 使用 `creatorOverview.gameCount`，代表已发布或维护中的游戏数量。
   - 统计数字使用现有 GameHub 数字格式，不制造示例数据。

3. **操作区**
   - 第一项为高辨识度的“个人中心”，跳转 `/my-account`。
   - 第二项为“我的主页”，跳转 `/games/author/:id`，保留原有头像点击的目的地。
   - 退出登录单独放在底部，并保持危险操作的 hover/focus 反馈。

浮层右边缘与顶栏账户容器对齐，宽度使用 `min(18.5rem, calc(100vw - 1rem))`，避免靠近右侧时超出视口。移动端维持同一信息顺序，统计区不改为横向滚动。

## 数据与状态

不新增后端接口和数据库字段。

- `followingCount` 与 `followersCount` 来自登录用户的 `account` 对象；缺失值安全回退为 `0`。
- 增加一个 `gameCount` signal，初始为 `null`。
- 头像浮层首次打开时复用当前 `loadGameCoinBalance()` 请求：成功时同时写入 `coinBalance` 与 `gameCount`；失败时硬币保持现有 `0` 回退，游戏数量保持 `null`，界面显示 `-` 而不是把网络失败误报为零个游戏。
- 保持现有一次性请求保护和登出清理逻辑，避免重复请求或切换账号后显示旧账号的游戏数。

状态覆盖：

- 初始/未打开：不挂载浮层。
- 打开加载中：身份和关注关系立即显示，动态数字保留固定宽度并显示骨架占位。
- 请求成功：显示真实游戏数量和硬币余额。
- 请求失败：动态数量显示 `-`，其余可用信息仍可操作；不阻断个人中心、我的主页和退出登录。
- 登出成功：立即卸载浮层并清空游戏数量和硬币缓存。

## 可访问性与交互细节

- 头像按钮提供 `aria-label="打开个人菜单"`、`aria-expanded` 和 `aria-controls`。
- 浮层使用稳定的 `id`，身份标题使用唯一 `id`，通过 `aria-labelledby` 建立关联；浮层不设置 `aria-modal="true"`，因为它不是模态对话框。
- 统计区是信息展示，不设置虚假的 button 或 link role。
- “个人中心”“我的主页”和“退出登录”均为真实可聚焦的链接或按钮，图标保持 `aria-hidden="true"`。
- 通过 `:focus-visible` 提供可见焦点环，触控目标保持至少 44px 高度。
- 浮层淡入淡出继续遵守 `prefers-reduced-motion: reduce`，减少动画时直接切换状态。

## 非目标

- 不新增会员等级、B 币或不存在于当前 API 的字段。
- 不把“动态”改成消息通知数，也不新增独立动态统计接口。
- 不改动 `/my-account`、`/games/author/:id` 的路由结构。
- 不重做非游戏态的 PeerTube 账户下拉菜单。

## 验收标准

- 登录状态下点击头像可以打开和关闭弹窗，不会直接导航。
- 弹窗可看到“个人中心”、关注数、粉丝数和动态数；动态数与 `gameCount` 一致。
- “个人中心”跳转 `/my-account`，“我的主页”跳转当前账号作者页。
- 鼠标 hover、Tab、Enter/Space、Escape 操作均可完成打开、浏览和关闭。
- 加载、请求失败、登出状态不会残留旧游戏数量。
- 桌面端和窄屏端没有水平溢出，焦点环、颜色和 reduced-motion 行为可验证。
- 通过相关单元测试、客户端 lint、客户端构建及真实浏览器交互验证。
