# GameHub 全局 UI 样式统一设计

日期：2026-08-29

## 背景与目标

GameHub 当前的主要页面已经采用“Bilibili 蓝·轻画布”视觉方向，但样式是在多次局部迭代中逐步形成的。当前代码同时存在 GameHub `--game-*` 令牌、PeerTube `pvar(--*)`/Bootstrap mixin、PrimeNG 默认覆盖和页面内硬编码值，造成颜色、圆角、阴影、控件高度、状态反馈与响应式间距在相邻页面之间不一致。

本次目标是统一当前 GameHub SPA 的视觉基础和页面表现，同时保留现有信息架构、路由、交互语义和已经稳定的游戏运行舞台。改造应让新页面只需要选择明确的语义令牌或基础样式，不再复制一套近似但不同的视觉值。

## 范围与排除项

纳入当前可由 GameHub SPA 访问的页面和浮层：

- 顶栏、游戏导航、头像菜单、通知/收藏/历史弹窗；
- 首页/发现、搜索、游戏详情/游玩、作者空间、收藏/历史、排行榜、动态、标签；
- 评论/讨论、活动、文章、投稿、创作中心、审核、分析、通知和预约；
- 登录、注册、找回密码、重置密码、个人中心、账户设置、关于页和 404；
- 全局 Toast、确认框、通用 Modal、下拉、表单、加载/空数据/错误状态。

排除未被 SPA 路由加载的 `client/src/standalone/**` 视频时代构建产物。游戏运行 iframe 内部的深色舞台、截图预览和第三方分享品牌色属于明确语义特例，只统一容器尺寸、状态和交互边界，不强行改成浅色画布。

## 设计原则

### 1. 单一视觉语义层

以现有 `client/src/app/+games/game-community.tokens.scss` 为 GameHub 令牌源，补齐以下语义类别：画布/表面、文本阶层、边框、品牌行动、辅助行动、成功/警告/危险状态、焦点环、控件尺寸、内容间距、圆角阶梯、阴影阶梯和动效时序。组件只引用语义令牌；白色、黑色、透明、`50%` 圆形和运行舞台专用深色值只有在语义明确时保留。

不改变 PeerTube 主题系统对插件/遗留兼容页面的支持。通过 GameHub 页面作用域为 Bootstrap、PeerTube 表单 mixin 和 PrimeNG 浮层建立兼容映射，使登录、重置密码、共享表单、下拉和 Toast 能消费同一套 GameHub 变量，而不是在每个组件里继续使用 `!important` 叠加覆盖。

### 2. 统一基础控件

建立可复用的 GameHub surface/control/state 样式契约：

- Surface：页面画布、标准内容卡、次级表面、浮层表面分别使用固定背景、边框和阴影等级；
- Control：主按钮、次按钮、幽灵/文字按钮、危险按钮、输入框、选择框和关闭按钮统一高度、内边距、圆角、字体重量、悬停/按下/禁用/焦点状态；
- State：加载骨架、空状态、错误提示、成功反馈和警告提示统一图标位置、文字层级、间距和语义色；
- Layout：页面内容宽度、section 标题、工具栏、网格间距和移动端边距使用共享节奏，不改变现有页面信息顺序。

优先复用现有 Angular 组件边界和 CSS 类名；只有类名本身阻碍统一或造成真实歧义时才做模板级调整。避免为了抽象而新增依赖或把页面特有布局强行合并成巨型组件。

### 3. 逐类迁移，而非全局替换

迁移顺序为：

1. 令牌和框架兼容映射；
2. 全局按钮、输入、Modal、Dropdown、Toast；
3. 顶栏和登录/账户流程；
4. 首页、卡片、详情/游玩和作者空间；
5. 社区、活动、文章、创作/管理和分析页面；
6. 关于、404、重置密码及剩余共享状态样式。

每一类先收敛重复的颜色/圆角/阴影/控件高度，再清理无引用或内联的旧样式。保留必要的视觉特例并用注释说明理由，避免把主题语义误判为残留样式。

### 4. 响应式和无障碍不回退

沿用当前桌面、平板和移动断点的产品行为，只将重复的间距和控件尺寸集中到共享变量。所有交互控件继续保留 `:focus-visible` 可见焦点、禁用态和至少 44px 的主要触控目标；动效继续尊重 `prefers-reduced-motion: reduce`。不以压缩内容或隐藏关键操作换取视觉整齐。

## 代码组织与数据流

令牌在全局应用样式中加载一次，浮层挂载到 `body` 时仍能继承；共享控件契约通过全局 GameHub 样式层和现有 PeerTube/Bootstrap/PrimeNG 变量映射提供。页面组件仍拥有自己的布局样式，只消费共享语义值。整体关系如下：

```text
GameHub tokens
    ├── active SPA scope / framework compatibility bridge
    ├── shared surface, control and state contracts
    └── page-local layout and intentional visual exceptions
```

不改 API、数据库、路由数据和业务状态。样式改动不得改变表单提交、权限判断、游戏 iframe 安全属性或导航弹窗生命周期。

## 验收标准

- 活动 SPA 页面不再出现未说明的旧橙/棕/靛紫硬编码作为基础 UI 色，品牌蓝/粉与状态色均来自语义令牌；
- 标准按钮、输入框、下拉、卡片、浮层、Toast 和状态块在相邻页面的高度、圆角、边框、阴影和焦点表现一致；
- 登录/注册/找回密码/重置密码与账户设置使用同一套表单和操作视觉语言；
- 首页卡片、详情页内容卡、社区卡片、作者页和管理/分析卡片遵守同一表面层级；
- 关键页面在桌面和移动宽度下无横向溢出，主要操作可见且可键盘访问；
- 游戏运行舞台和必要的第三方分享品牌色仍保持语义正确；
- `pnpm run verify:gamehub-client`、涉及文件的客户端 lint、构建和根目录 `pnpm run self-test:gamehub` 通过；
- 启动后的 `/api/v1/ping`、SPA 入口、懒加载脚本以及 Codex 内置浏览器中的代表性页面和交互通过检查；
- 不引入新依赖，不修改生成的 locale、dist、node_modules、既有 migration 或 lockfile。

## 验证范围

静态验证检查令牌使用、未引用样式和 GameHub 页面契约；构建验证检查 Angular/SCSS 编译和 server 兼容性。Codex 内置浏览器至少覆盖：未登录首页、搜索/分类、游戏详情、登录弹框、账户设置、一个社区列表/详情页、投稿或分析页，以及移动宽度；同时检查导航、弹框、表单焦点、加载/错误/空状态和无横向溢出。若当前运行环境没有可用的 Codex 内置浏览器，报告浏览器验收阻塞，不切换到 Chrome、Chrome CDP、Playwright 或其他独立浏览器工具。
