## 阶段 C：createAsyncState 增强与三态迁移（worktree: `refactor-async-state`）

### C1. 工具增强（先做，其他迁移依赖此）
修改 `client/src/app/+games/shared/async-state.ts`：
- **`error` 信号改为 `string` 类型**（统一与 comments-store 一致，保留 errorMessage 为 alias）
- **`load()` 增强支持 forkJoin**：接受多个 Observable 并发加载，返回合并结果（适配 games-home 的 6 源 forkJoin）
- **`loadMore()` 新方法**：支持分页追加（loadingMore 信号），适配 loadMoreRecommended
- **错误消息对接 `getGameActionErrorMessage`**：load() 的 error 回调调用此 helper 而非硬编码
- **`GameErrorRetryComponent` 增加 `@Input() message` 默认值对接** + 样式微调
- **验证**：单独编译通过

### C2. 迁移 10 个手动三态组件
按 ROI 排序迁移（每批迁移后验证 ng build）：
- **批次 1（高 ROI）**：games-home（64 行样板）、game-author（21 行）、game-rankings、game-library
- **批次 2（中 ROI）**：game-collections、game-collection-detail、game-following、game-manage、game-notifications、game-edit
- **批次 3（补齐 error 态）**：8 个 LOADING-ONLY 组件（game-activity-feed/game-articles/game-event-admin/game-event-detail/game-events/game-play/game-tags-cloud 等）接入 GameErrorRetryComponent
- **预期**：每个组件净减 15-40 行样板，消除 loading 卡死风险

## 并行执行策略

```
时间线：
  ├─ worktree 1: refactor-backend-split    → A1 + A2（后端，串行）
  ├─ worktree 2: refactor-frontend-split   → B1 + B2 + B3 + D1 + D2（前端，组件与样式交错）
```

## 验证标准（每阶段合并前）

1. **`tsc -b server/tsconfig.json`** — 0 错误（后端拆分）

4. **路由/行为不变** — 所有原有 API 路径和前端路由行为不变
5. **`git diff --check`** — 无空白错误
6. 提交信息中文，`type(scope): 描述` 格式
